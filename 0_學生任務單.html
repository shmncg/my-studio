Day 7｜讓按鈕自己去問 AI

上次你按「🧩 組好指令」，然後自己複製、自己貼給 AI、自己貼回來。很多人說：「還是很煩。」
今天做三件事：①把工作台放上網路，手機也打得開。②按鈕自己去問 AI，不用你跑腿；老師的額度用完，自動換你自己的 Gemini。③多請兩個 AI 進來：一個幫你改，一個幫你挑毛病。

這張任務單怎麼用
  • 黑色框框是要貼給 Codex 的話，按「複製」就好。【 】裡的字要換成你自己的。
  • 虛線框框是你的紀錄，打字會自動存在這台電腦的瀏覽器裡。
  • Codex 每做完一步，先用 Chrome 打開 index.html 試試，確定可以用，再做下一步。
  • 最後一節按最下面的「複製全部紀錄」，交到作業繳交區。
今天最重要的一條規則：今天會有兩把「AI 金鑰」：老師發的 OpenRouter（全班共用），和你自己的 Gemini。金鑰只能貼在工作台的 ⚙ 設定裡。不貼給 Codex、不貼到班群、不寫進任何檔案。老師那把外流，全班一起沒得用；你那把外流，別人用你的額度。

第 1 節｜把工作台放上網路（GitHub 網頁版）

09:10–10:00

GitHub 是什麼？一個放檔案的雲端倉庫。它有一個免費的功能叫 Pages：把 index.html 放上去，就變成一個網址，手機也打得開。

今天不用打指令，全部在網頁上點。

1. 建一個倉庫（repository）

  1. 登入 github.com。右上角「＋」→ New repository。
  2. Repository name 填 my-studio。
  3. 選 Public（公開）。這就是為什麼金鑰不能進檔案：公開＝全世界看得到。
  4. 其他都不要勾，按綠色 Create repository。

2. 把 index.html 拖上去

  1. 新倉庫的頁面上，找「uploading an existing file」這個連結，點它。（或右上「Add file ▾」→「Upload files」。）
  2. 打開你電腦的 my-studio 資料夾，把 index.html 這一個檔案拖進網頁。（只要這個檔案，不要拖整個資料夾、不要拖品牌規格。）
  3. 往下捲，按綠色 Commit changes。

3. 打開 Pages，拿到網址

  1. 倉庫上方的分頁點 Settings → 左邊選單點 Pages。
  2. 「Build and deployment」→ Source 選 Deploy from a branch。
  3. Branch 選 main，旁邊資料夾選 / (root)，按 Save。
  4. 等 1～3 分鐘，重新整理這一頁，上面會出現「Your site is live at …」。你的網址長這樣：https://你的帳號.github.io/my-studio/
打開是 404？再等一分鐘。等了五分鐘還是 404？看檔名是不是正好叫 index.html（小寫、沒有多的字）。

4. 手機打開

  1. 用手機打開你的網址。
  2. 你會發現：⚙ 設定是空的、存過的貼文也不在。為什麼？
答案：設定和貼文是存在「瀏覽器」裡的，而且是跟著網址走的。電腦上的 index.html 是一個網址，github.io 是另一個網址，手機又是另一台裝置。所以上網路的版本要再貼一次設定。（今天第 7 節會做。）

第 2 節｜改一點再上傳，然後回到上一版

10:10–11:00

上次有人說「好的版本改一改就不見了」。GitHub 的另一個好處：每次上傳，它都幫你留一個存檔點，像遊戲存檔。壞掉了，可以回到上一版。

1. 改一個小地方

請把標題列的標題，在品牌名稱後面加上「v2」。其他地方不要動。

Chrome 打開 index.html，看到 v2 再往下。

2. 再上傳一次（同一個檔名，就是蓋過去）

  1. 倉庫首頁 → Add file ▾ → Upload files → 拖 index.html → Commit changes。
  2. 等 1 分鐘，打開你的網址，按 Ctrl＋F5（強制重新整理）。看到 v2 了嗎？

3. 看歷史，回到上一版

  1. 倉庫首頁點 index.html → 右上角 History。你會看到兩筆（兩個存檔點）。
  2. 點舊的那一筆右邊的 <> 圖示（Browse the repository at this point）。
  3. 點 index.html → 右上角的 ⤓ Download raw file。這就是舊版，下載到電腦。
  4. 把這個舊版再上傳一次（蓋過去）。等一分鐘，網址上的 v2 不見了嗎？
  5. 練習完，把電腦裡的新版（有 v2 的）再上傳回去。
記住這個順序：History → 點舊的 → 下載 → 再上傳。以後改壞了，一分鐘救回來。
✏️ 第 2 節 用一句話說：「上傳到 GitHub」等於什麼？
⭐ 快的人：叫 Codex 用 git 指令上傳，不用拖檔案。（電腦要先裝 git；沒裝的話這題跳過。）
請幫我把這個資料夾用 git 連到我的 GitHub 倉庫 https://github.com/【我的帳號】/my-studio，只上傳 index.html，不要上傳其他檔案（用 .gitignore 擋掉）。一步一步告訴我要做什麼，需要我登入的地方說清楚。

請加「💬 AI 小幫手」，放在貼文框下面： 1. 四個快捷按鈕：「短一點」「換開頭」「少一點 emoji」「更像範例」；一個輸入框＋「送出」按鈕；上面有對話紀錄（我說的、它回的）。 2. 送出時，用跟 ✨ 一樣的方式呼叫 AI，但 messages 這樣組： - 第一則 role 是 "system"：「你是【品牌名稱】的小編助理。使用者會叫你修改一篇【目前平台】貼文。只改使用者要求的地方，其他保持原樣；不能加素材卡上沒有的事實；遵守品牌規格；一律用台灣的繁體中文和台灣用語。不要出現簡體字，也不要用大陸用語（例如：視頻→影片、質量→品質、優化→改善、信息→訊息、網絡→網路、用戶→客人或使用者）。只回覆改好以後的整篇貼文，不要解釋、不要加標題。」後面接品牌規格全文和素材卡全文。 - 中間：之前的對話（最多留 8 則）。 - 最後一則 role 是 "user"：「目前的【平台】貼文：（貼文全文）。請這樣改：（我打的那句）」。 3. 回來的文字，直接換掉「目前這個平台」的貼文框，預覽跟著變。換掉之前先存「上一版」（見第 6 點）。 4. 這個平台還沒有貼文就不要送，提醒「先讓 AI 寫一篇」。 5. 對話紀錄跟著這一篇自動暫存。 6. 貼文框下面加「↩ 復原上一版」：AI（✨ 和小幫手）每次要換掉貼文之前，先把三個平台現在的內容存成「上一版」；按了就換回去（再按一次換回來）。 7. 小幫手一樣用第 4 節那個「問 AI」函式，OpenRouter 失敗會自動換 Gemini。 其他地方不要動。

試用：改五次

  1. 按「短一點」。看手機預覽。
  2. 按「換開頭」。
  3. 自己打一句：「把價格放到第一句」（或你品牌的某件事）。
  4. 再打：「再短一點」。它知道「再」是接著上一句嗎？（對話紀錄有用嗎？）
  5. 按 ↩ 復原上一版。回去了嗎？

第 6 節｜🔍 檢查官：第二個 AI 專門挑毛病

15:10–16:00

為什麼不叫寫的那個 AI 自己檢查？自己改自己的作業，都會給自己 100 分。所以請第二個 AI，角色不同（審核官）、指令不同（只准挑毛病），拿著你的檢查清單一條一條對。

它回的格式要固定（每條一行：編號、✅❌⚠️、一句話），工作台才能把 ❌ 標紅、⚠️ 標黃。

請加「🔍 檢查官」按鈕，放在貼文框下面： 1. 按了以後，第二次呼叫 AI（跟寫貼文的不是同一次對話），messages 這樣組： - system：「你是【品牌名稱】的審核官，專門挑毛病，不負責誇獎。把每一篇貼文照檢查清單一條一條對。✅ 符合；❌ 不符合（寫出哪一句有問題、該怎麼改）；⚠️ 要靠人判斷的，先給意見。回覆格式：【平台名稱】換行，然後每條一行「編號 符號 一句話」，最後【總結】列出要人工確認的事。不管清單有沒有寫，都另外檢查有沒有簡體字或大陸用語。報告也用台灣繁體中文寫。」 - user：品牌規格全文＋素材卡全文＋設定裡的檢查清單（沒填就用內建六條：日期價格對不對、有沒有多加的事、只能在某平台講的有沒有跑掉、先不要講的有沒有出現、有沒有不能用的字、有沒有簡體字或大陸用語）＋每個平台的貼文（用【FB】【IG】【LINE】分開）。 2. 回來的報告跳出一個視窗顯示：有 ❌ 的那行紅底、有 ⚠️ 的那行黃底。 3. 沒有任何貼文時不要送，提醒「還沒有貼文可以檢查」。 其他地方不要動。
